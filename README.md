# OAC Extensions

Custom visualization extensions for **Oracle Analytics Cloud (OAC)** and
**Oracle Analytics Desktop (OAD)**, built at Washington State University for
academic-pathway and institutional analytics. MIT licensed.

The plugins are domain-agnostic: they read whatever you drop into their
grammar buckets. The examples and reviewer guide happen to use course-pathway
data, because that is what they were built to explain.

## The extensions

| Extension | Root id | Version | What it does |
|---|---|---|---|
| **WSU Network** | `com-wsu-network` | 1.2.2 | Directed, weighted transition graph (vis-network). Repeat self-loops, expanded repeat stages, terminal "no further step" routing, edge-type legend, large-graph stabilization. |
| **WSU Sankey** | `com-wsu-sankey` | 1.1.2 | Explicit-stage Sankey: Start → up to five Intermediate → End buckets. Incomplete-path routing and highlight, threshold / Top-N noise control, click-to-focus upstream/downstream. |
| **WSU Line** | `com-wsu-line` | 1.2.2 | Multi-series line with a shared-X tooltip table (sortable, with vs-average / rank / year-over-year deltas), drag-to-zoom, header attribute chips, parameter-driven value labels. |
| **WSU Dumbbell** | `com-wsu-dumbbell` | 1.1.2 | Paired before/after comparison from wide (two measures) or long (role column) data. In-chart sort/filter strips, group aggregation, small multiples. |
| **WSU Lattice Scatter** | `com-wsu-lattice-scatter` | 1.1.2 | Course × term lattice with grade-letter or grade-point markers per student row. |
| **WSU Glossary Pivot** | `com-wsu-glossary-pivot` | 0.19.0 | Pivot table with a glossary tooltip on headers. Rows, columns, and values; click-to-sort; totals with per-measure rules (sum, average, weighted, ratio); alignment, word-safe wrapping, and column/table widths; per-column data bars; show a measure as % of total; hide a field without dropping it from the query; rename the field title. Number format groups thousands. Print PDF prints this table. Print Canvas prints every Glossary Pivot on the active canvas tab. Versioned on its own line, not with the 1.x plugins. |

Source for each lives in `oac-sdk-dev/src/customviz/<root id>/`. Each has a
reference spec in `docs/plugins/`.

## Install a pre-built extension

You do not need the SDK to *use* these. Download the zip for the extension you
want from the [Releases](../../releases) page, then:

- **OAC:** Navigator → Console → Extensions → **Upload Extension** → choose the
  zip. Requires the BI Service Administrator role. Users reload their browser.
- **OAD:** hamburger menu → Console → Extensions → **Upload Extension** →
  choose the zip → **restart OAD** (the extension registry is cached).

The visualizations appear under the **WSU** category in the visualization
gallery. Uploading a zip with the same root id replaces the installed version
(the Console asks to overwrite). **Tested behavior, not a contract:** on OAD
26.01 the 1.0.0 → 1.1.1 upgrade replaced in place and saved workbooks kept
their bucket bindings and settings. Oracle documents upload, delete and
recovery but not a compatibility guarantee, and does not say when an open
browser session starts running the new code. `docs/guides/oac_dev_verification.md`
§2 is the procedure for establishing both on your tenant before a production
upload.

## Try it with the synthetic dataset

`examples/mock_math_pathway_200_students.csv` is a 200-student, 855-row

`tools/generate_mock_math_pathway.py`; no real data). It carries ready-made

## Build from source

### Prerequisites

- Windows (the build scripts are PowerShell; Gradle itself is cross-platform)
- [Oracle Analytics Desktop](https://www.oracle.com/solutions/analytics/analytics-desktop/oracle-analytics-desktop.html)
  — download goes through Oracle eDelivery: sign in (or create a free Oracle
  account), pick the Windows x64 platform, accept the license, and download
  via the Download Manager as a zip — not a direct installer download.
  Extract the zip and run the installer inside it. Ships the SDK tools under
  `<OAD install>\tools`. **Deprecated by Oracle:**
  no downloads after December 2026; the final version (January 2026, 26.01)
  is the one this repository was built with. Archive the installer. See
  `docs/oac_design.md` §6.32 for what that means for this build.
- A JDK 17 (OAD's bundled JDK at `<OAD install>\OracleBI1\jdk`, or any
  standalone JDK 17)
- Node.js (only for the `node --check` syntax step)

### One-time setup

```powershell
git clone https://github.com/gcrouch-wsu/OAC-Extensions.git
cd OAC-Extensions\oac-sdk-dev
Copy-Item gradle.properties.example gradle.properties
# edit gradle.properties: sdkDir and desktopDir must point at your OAD install
```

`gradle.properties` is git-ignored because the paths are machine-specific.

### Build

```powershell
cd oac-sdk-dev
$env:JAVA_HOME = "C:\path\to\jdk-17"   # optional; script falls back to a default
.\build-sdk.ps1
```

Gradle validates every plugin under `src/customviz/`, generates `plugin.xml`
from the JSON manifests, and writes one zip per plugin to
`oac-sdk-dev\build\distributions\customviz_<root id>.zip`. A full build
takes a couple of minutes.

Before building, a cheap sanity check catches the two most common failures
(a JS typo or a malformed manifest — both otherwise show up as a blank viz):

```powershell
cd src\customviz\com-wsu-network
node --check wsuNetwork.js
node --check wsuNetworkdatamodelhandler.js
Get-Content extensions\oracle.bi.tech.plugin.visualization\com-wsu-network.json -Raw | ConvertFrom-Json -ErrorAction Stop
Get-Content extensions\oracle.bi.tech.plugin.visualizationDatamodelHandler\com-wsu-network.visualizationDatamodelHandler.json -Raw | ConvertFrom-Json -ErrorAction Stop
```

### Run the model tests

`oac-sdk-dev/tests/` holds a host-independent regression harness: it loads
each plugin's AMD module in Node with the `obitech-*` framework replaced by
stubs and exercises the model, aggregation and layout code with synthetic
data. Every test encodes a defect found in review so it cannot return.

```powershell
cd oac-sdk-dev
node tests
un.js
```

No dependencies beyond Node. Host behavior (rendering, property panel,
marking) still needs OAD/OAC.

### Iterate without packaging

`.\run-sdk.ps1` launches OAD in SDK mode with `-pluginDevDir` pointed at
`src/`, so plugins load directly from source. Edit, then close and reopen the
workbook (restart OAD after manifest changes). In OAD, F12 → Console and filter
on the module name (e.g. `com-wsu-network/wsuNetwork`) to see the plugin's
logger output.

## Anatomy of a plugin

```
src/customviz/com-wsu-network/
  extensions/
    oracle.bi.tech.plugin.visualization/com-wsu-network.json                # manifest: name, category, icon, JS entry
    oracle.bi.tech.plugin.visualizationDatamodelHandler/…Handler.json        # grammar: the drop buckets and their limits
  wsuNetworkdatamodelhandler.js   # maps buckets onto physical row/column/data edges
  wsuNetwork.js                   # the visualization: render(), property panel, marking, tooltips
  wsuNetworkstyles.css
  nls/root/messages.js            # strings
  wsuNetworkIcon.png
  lib/vis-network.min.js          # third-party (Network only)
```

The root id (`com-wsu-network`) must match `viz:chart.type` in the manifest
exactly, or the plugin uploads but never appears. `docs/oac_design.md` §3 and
§6.2 have the full rename checklist for forking a plugin.

## Learning from Oracle's samples

Oracle publishes ~25 sample extensions (force-directed graph, org chart, lines
on map, calendar, funnel, …) in the
[Oracle Analytics Extensions Library](https://www.oracle.com/business-analytics/data-visualization/extensions/),
and the SDK's `bicreateenv` generates a starter (`sample-circlepack`). They are
Oracle-copyrighted and **not redistributed here**; download them yourself and
keep them in a local, non-committed folder. `docs/oac_design.md` cites several
by name where they illustrate a pattern.
